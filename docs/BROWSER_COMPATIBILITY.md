The WebKit trace recorded a successful document HTTP response followed by an unresponsive page after inspector-aborted media requests; this is evidence of an automation/runtime interaction, not proof of a specific application defect. The follow-up uses completed HTTP 404 responses for unavailable external assets, waits for the mute state to update, bounds failure diagnostics and retains failure traces immediately. The completed-HTTP follow-up produced an inspectable Profile failure: automatic smooth scrolling moved an Edit control under the sticky header and the click missed. A shared `scripts/qa-browser-helpers.cjs` now waits for finite ancestor animations, positions the control with an instant test scroll, and performs one genuine pointer click. No application assertions were removed, forced clicks or action retries were added, or production styling was changed.

Reproduction after installing Playwright and its browser dependencies:

```sh
pnpm check
pnpm test
pnpm build
QA_BROWSER=chromium pnpm test:navigation
QA_BROWSER=chromium pnpm test:workflows
QA_BROWSER=chromium pnpm test:interactions
```

Repeat with `QA_BROWSER=firefox` and `QA_BROWSER=webkit`. Set `PLAYWRIGHT_MODULE` to an isolated installation when it is not on the module search path. `.github/workflows/browser-compatibility.yml` performs this setup automatically.
